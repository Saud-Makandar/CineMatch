# 🎬 CineMatch: Movie Recommendation & Analytics System
**Intelligent Data Systems I (IDS-I) Lab Mini-Project**

An end-to-end, reproducible Movie Recommendation System and Analytics project built purely using core scientific Python libraries (**NumPy**, **Pandas**, **SciPy**, **Scikit-Learn**, **Matplotlib**, and **Seaborn**).

---

## 📌 Project Overview
CineMatch implements **Item-Based Collaborative Filtering** powered by **K-Nearest Neighbors (KNN)** using **Cosine Similarity**, evaluated against a rigorous **IMDB Weighted Popularity Baseline**, and accompanied by statistical exploratory data analysis (EDA).

### 🔑 Key Features
- **Pure Item-Based Collaborative Filtering:** Finds similar movies based on how users rated them using K-Nearest Neighbors and Cosine Similarity.
- **Data Preprocessing & Sparsity Reduction:** Filters sparse interaction noise, taking matrix sparsity from **98.30% down to 94.14%**.
- **Descriptive Statistical Analysis:** Analyzes central tendency, dispersion, variance, and skewness of explicit rating distributions.
- **Exploratory Data Visualizations:** Generates rating distributions, genre breakdowns, and user activity curves using Matplotlib and Seaborn.
- **Quantitative Model Evaluation:** Evaluates offline performance using **Precision@K** and **Recall@K** on real held-out user interactions.
- **Automated Unit Testing:** 8 automated test cases covering schema integrity, math formulas, recommendations, and edge cases.

## 📊 Dataset Schema & Preprocessing

The project utilizes the benchmark MovieLens dataset (`parasharmanas/movie-recommendation-system`):

### 1. Raw Schema
- **`movies.csv` (9,742 rows):**
  - `movieId` (*int*): Unique identifier.
  - `title` (*str*): Movie title including year, e.g., `"Toy Story (1995)"`.
  - `genres` (*str*): Pipe-delimited genre categories, e.g., `"Adventure|Animation|Comedy"`.
- **`ratings.csv` (100,836 rows):**
  - `userId` (*int*): Anonymized user identifier (610 unique users).
  - `movieId` (*int*): Target movie identifier.
  - `rating` (*float*): Explicit score from 0.5 to 5.0 (0.5 star increments).
  - `timestamp` (*int*): Epoch seconds when rating was submitted.

### 2. Preprocessing & Cleaning Steps
1. **Deduplication:** Dropped duplicate `movieId` entries and repeated user-item pairs.
2. **Column Pruning:** Removed `timestamp` since collaborative filtering operates on interaction matrices.
3. **Feature Engineering:** Extracted 4-digit release year `year` from `title` via regex.
4. **Sparsity & Noise Filtering:**
   - Real-world interaction matrices are over 98% empty. Movies with very few ratings introduce statistical noise.
   - Filtered to include movies with $\ge 10$ ratings and users with $\ge 5$ ratings.
   - **Initial Matrix Sparsity:** $98.30\%$
   - **Filtered Matrix Sparsity:** $94.14\%$ (2,269 movies $\times$ 610 users).
5. **CSR Compression:** Stored the 2D pivot table in Compressed Sparse Row (`scipy.sparse.csr_matrix`) format for memory-efficient distance computation.

## 🧠 Algorithms & Mathematical Formulation

### CineMatch KNN (Item-Based Collaborative Filtering)
Item-based collaborative filtering measures how similarly two movies are rated across the entire user base.

- Let vector $\vec{u} = [r_{u,1}, r_{u,2}, \dots, r_{u,n}]$ represent the ratings given to movie $A$ by all users.
- Let vector $\vec{v} = [r_{v,1}, r_{v,2}, \dots, r_{v,n}]$ represent ratings given to movie $B$.

**Cosine Similarity:**
$$\text{Cosine Similarity}(\vec{u}, \vec{v}) = \frac{\vec{u} \cdot \vec{v}}{\|\vec{u}\|_2 \|\vec{v}\|_2} = \frac{\sum_{i=1}^{n} r_{u,i} r_{v,i}}{\sqrt{\sum_{i=1}^{n} r_{u,i}^2} \sqrt{\sum_{i=1}^{n} r_{v,i}^2}}$$

**Cosine Distance (Loss / Metric):**
$$\text{Cosine Distance} = 1 - \text{Cosine Similarity}(\vec{u}, \vec{v})$$

The Nearest Neighbors model queries the $K$ movies with the minimum Cosine Distance (maximum Cosine Similarity) to the input vector.

## 📈 Quantitative Model Evaluation

We split active user histories into **80% Train** and **20% Test** interactions, defining an item as **Relevant (Ground Truth)** if $\text{Rating} \ge 3.5$.

$$\text{Precision@K} = \frac{|\text{Top } K \text{ Recommendations} \cap \text{Relevant Test Items}|}{K}$$

$$\text{Recall@K} = \frac{|\text{Top } K \text{ Recommendations} \cap \text{Relevant Test Items}|}{|\text{Total Relevant Test Items}|}$$

### Actual Evaluation Results (Evaluated on Active Test Users):

| Metric | CineMatch KNN Performance |
| :--- | :---: |
| **Precision@5** | **6.89%** |
| **Recall@5** | **3.67%** |
| **Precision@10** | **5.27%** |
| **Recall@10** | **6.02%** |

### Evaluation Takeaways:
1. **Precision vs. Recall Trade-Off:** As $K$ grows from 5 to 10, **Recall increases** (from 3.67% to 6.02%) because more relevant items are retrieved, while **Precision adjusts** because earlier ranks contain the highest-similarity neighbors.

## 🎓 Viva & Lab Exam Preparation (FAQ)

### Q1: What is Collaborative Filtering?
> **Answer:** Collaborative Filtering makes recommendations based on user interaction patterns. It assumes that if users had similar tastes in the past (rating the same movies similarly), they will agree on other movies in the future.

### Q2: Why Item-Based Collaborative Filtering instead of User-Based?
> **Answer:** 
> 1. Item-item relationships are far more stable over time than user profiles.
> 2. The number of items is generally smaller and more static than the number of active users, allowing efficient offline precomputation.
> 3. Item-based models avoid user preference drift.

### Q3: Why use Cosine Similarity instead of Euclidean Distance?
> **Answer:** Euclidean distance is biased by absolute rating numbers (a strict rater who gives 2–3 stars vs. a generous rater who gives 4–5 stars would appear far apart). Cosine similarity measures the angle between vectors, capturing relative preference patterns regardless of scale.

### Q4: What is the Sparsity Problem and how did we handle it?
> **Answer:** Sparsity occurs because any individual user only rates a tiny fraction of all available items (98.30% of the raw matrix is empty). Extreme sparsity causes similarity measures to become noisy. We solved this by filtering out movies with fewer than 10 ratings and users with fewer than 5 ratings, reducing sparsity to 94.14%.

### Q5: What is the Cold-Start Problem?
> **Answer:** Cold-start occurs when a new user or new item enters the system with zero interaction history. Because collaborative filtering needs past ratings, it cannot construct vector representations. We address this using genre metadata filtering and seed query matching until sufficient interaction ratings are collected.
